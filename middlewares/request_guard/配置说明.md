# request_guard 配置说明（config.json）

> 本文件是「请求守卫」中间件的**唯一配置文件**，位于 `middlewares/request_guard/config.json`。
> 中间件**只在启动时读取一次**，改完配置需重启服务才生效。
> 若字段缺失或写错，会自动用内置默认值兜底，不会崩溃。

---

## 一、整体结构速览

```jsonc
{
    "enabled": true,            // 总开关
    "admin": { ... },           // 管理后台
    "trusted_headers": [...],   // 真实IP取值来源
    "log": { ... },             // 请求日志
    "rate_limit": { ... },      // 请求频控
    "identity": { ... },        // 身份差异化(三形态动作)
    "spider_keywords": { ... }, // 蜘蛛识别词库
    "rules": [ ... ]            // ⚠️ 预留字段，别手改，用后台管理
}
```

---

## 二、逐字段详解

### 1. `enabled` —— 总开关
| 值 | 效果 |
|---|---|
| `true` | 整个守卫生效（记录日志、执行规则等） |
| `false` | 完全放行，不记录、不拦截（后台页面也不可用） |

默认：`true`

---

### 2. `admin` —— 管理后台设置
```jsonc
"admin": {
    "path": "request-guard",   // 后台访问地址的前缀
    "password": "123456",      // 登录密码（明文，请改成自己的）
    "session_key": "rg_admin_ok" // 登录成功后的会话标记名(一般不用改)
}
```

| 字段 | 说明 |
|---|---|
| `path` | 后台访问路径。改成 `myadmin` 后，访问地址就是 `http://你的域名/myadmin/`。改这里等于"隐藏后台入口" |
| `password` | 登录密码。⚠️ **明文保存**，建议改成复杂密码，且不要把 config.json 提交到公开仓库 |
| `session_key` | 登录成功写入 session 的键名。只有改动了源码里对应的判断逻辑才需要动它 |

后台登录页自动出现在：`/request-guard/login/`

---

### 3. `trusted_headers` —— 真实 IP 取值来源
```jsonc
"trusted_headers": ["HTTP_X_FORWARDED_FOR", "HTTP_X_REAL_IP", "HTTP_CF_CONNECTING_IP"]
```
按顺序逐个检查这些请求头，取到值就用它当真实 IP（用于日志、封禁、频控）。

- **为什么需要**：如果网站挂了 CDN / 反向代理 / Cloudflare，`REMOTE_ADDR` 拿到的是 CDN 的 IP 而不是访客真实 IP。
- `HTTP_X_FORWARDED_FOR`：最常见的代理头，取最左边第一个 IP。
- `HTTP_X_REAL_IP`：Nginx `proxy_set_header X-Real-IP $remote_addr` 设置的。
- `HTTP_CF_CONNECTING_IP`：Cloudflare 专用。
- 全部取不到时才退回 `REMOTE_ADDR`。

> 注意：列表里的头如果来源不可信，可能被伪造。只保留你确实在用的代理层提供的头。

---

### 4. `log` —— 请求日志
```jsonc
"log": {
    "enabled": true,
    "exclude_paths": ["/static/", "/media/", "/favicon.ico", "/robots.txt", "/sitemap.xml"],
    "keep_days": 7,
    "max_rows": 500000,
    "exclude_ips": []
}
```

| 字段 | 说明 |
|---|---|
| `enabled` | `false` 则不写日志（规则拦截仍生效，但不留痕） |
| `exclude_paths` | **这些路径的普通请求不写日志**，避免被 css/js/图片刷爆。两点注意：① 以 `/` 结尾的按前缀匹配，如 `/static/` 会排除所有 `/static/xxx`；② 即使路径在排除列表里，**被拦截/伪装处置的请求仍会记录**（便于追溯攻击） |
| `keep_days` | 自动清理：只保留最近 N 天的日志（每天首次写日志时触发检查） |
| `max_rows` | 兜底上限：表总行数超过该值就删除最旧的（双保险）。`0`=不启用条数上限 |
| `exclude_ips` | 这些 IP **完全放行且完全不记录**（适合放你自己的运维 IP/服务器 IP） |

---

### 5. `rate_limit` —— 请求频控（防刷）
```jsonc
"rate_limit": {
    "enabled": false,         // ⚠️ 默认关闭，按需开启
    "per_ip_per_minute": 180, // 单 IP 每分钟最多请求数
    "ban_minutes": 10         // 超过后临时封禁多少分钟
}
```

| 字段 | 说明 |
|---|---|
| `enabled` | `true` 才启用。**默认关**：开错阈值容易误伤正常用户/蜘蛛 |
| `per_ip_per_minute` | 滑动窗口统计，同一 IP 1 分钟内超过 N 次 → 触发 |
| `ban_minutes` | 触发后该 IP 临时封禁（403）的分钟数，到期自动解除 |

⚠️ 限制说明：封禁状态存在**进程内存**里，重启服务即清零；多进程/多台机器部署时各自独立。触发记录会写入日志，原因标注 `rate_limit`。

---

### 6. `identity` —— 身份差异化（核心）
```jsonc
"identity": {
    "spider":      "pass",   // 搜索引擎蜘蛛（Baiduspider/Googlebot...）
    "human_ref":   "pass",   // 真人访问且带来源 Referer
    "direct":      "pass",   // 直接访问（无 Referer）
    "unknown":     "pass",   // 无法识别（如 UA 为空）
    "disguise_template": "request_guard/cloak_default.html" // 伪装页模板
}
```

四种身份怎么判定：
| 身份 | 判定逻辑 |
|---|---|
| `spider` | UA 命中下文的 `spider_keywords` 词库 |
| `human_ref` | 不是蜘蛛，且请求带 Referer |
| `direct` | 不是蜘蛛，且没有 Referer（地址栏直输/App 内打开/脚本访问都算） |
| `unknown` | UA 为空等无法判断的极端情况 |

每种身份可配的动作：

| 动作值 | 效果 |
|---|---|
| `pass` | 放行，正常返回页面（仅打标签记录） |
| `block` | 直接 403 拒绝 |
| `disguise` | 返回 `disguise_template` 指定的伪装页（HTTP 200，页面内容与真实站无关） |

**典型玩法**：
- 不想让"无来源直连"看到真实内容：
  `"direct": "disguise"` → 直连访客看到伪装页，带来源的真人和搜索引擎蜘蛛看真实页面。
- 想把无法识别的空 UA 直接拒绝：`"unknown": "block"`。

⚠️ `disguise_template`：填写 Django 模板名（放哪个 app 的 templates 下都可以）。包内自带 `request_guard/cloak_default.html`（"系统检查中"页面）。可以新建自己的伪装模板后把名字填到这里。

> 提醒：**对搜索引擎显示与真实用户不同内容的"欺骗式斗篷"违反百度/Google 站长指南，有被整站降权/清退风险**。以上 `spider` 建议保持 `pass`。

---

### 7. `spider_keywords` —— 蜘蛛识别词库
```jsonc
"spider_keywords": {
    "baidu":     ["baiduspider"],
    "google":    ["googlebot"],
    "bing":      ["bingbot", "msnbot"],
    ...
    "generic":   ["spider", "bot", "crawler", "crawl", "slurp", "spider"]
}
```
格式：`"蜘蛛显示名": ["UA关键词1", "关键词2", ...]`。UA 不区分大小写，**包含任意关键词即判为该蜘蛛**。

| 字段 | 说明 |
|---|---|
| key | 蜘蛛名，会显示在后台"蜘蛛"列，也会按它做统计 |
| value 数组 | 匹配 UA 的关键词列表。可按需增删，比如加新搜索引擎 |

内置列表：baidu / google / bing / sogou / 360 / bytespider(头条) / yisou / yandex / petal / semrush / ahrefs / mj12 / duckduckgo / facebook / twitter / linkedin / archiver / generic。
`generic` 里的 `bot`、`spider` 等通用词负责兜底（建议保留）。

---

### 8. `rules` —— ⚠️ 预留字段
```jsonc
"rules": []
```
**当前请不要手动编辑此字段。** 实际生效的处置规则都存在数据库（SQLite）里，通过后台 **规则管理** 页面增删改，支持：
- 匹配对象：IP / UA / 来源域名 / 路径
- 匹配方式：包含 / 完全等于 / 开头 / CIDR段(仅IP) / 正则
- 处置动作：403拦截 / 伪装页 / 302跳转 / 仅记录不拦截
- 附加：备注、启停开关、过期时间、命中计数

---

## 三、判定优先级（重要）

对同一次请求，按以下顺序**只执行第一个命中项**：

```
① 数据库处置规则(BlockRule)  → 命中则执行该规则动作
② 请求频控(rate_limit)       → 超限则 403
③ 身份策略(identity)         → 按上面身份配置的动作
④ 都没有命中                 → 放行
```

- 后台自身路径（`admin.path`）**完全豁免**：不记录、不拦截。
- 管理规则在后台操作即可，无需改 config.json。

---

## 四、进阶：把配置文件放到别处
默认读取包内的 `config.json`。若想每个站点各自放一份，可用环境变量指向：

```
REQUEST_GUARD_CONFIG=/绝对路径/你的config.json
```

---

## 五、改完配置怎么生效？
1. 编辑 `config.json`；
2. **重启** Django 服务（`python manage.py runserver` 或重启 uwsgi/gunicorn）；
3. 用浏览器访问后台验证效果。

# 六、部署教程

> 目标场景：把 `request_guard` 装进**一个新的 Django 克隆站**（别人拿到你的项目/包后按下面步骤操作即可）。
> 本仓库已经部署好了，可直接对照本仓库的 `ToHuaShunDownload/` 改动来抄作业。

## 步骤 1：拿到并放好代码
把整个 `middlewares/request_guard/` 目录（含 `templates/`、`static/`、`migrations/`）复制到你的 Django 项目根目录：

```
你的项目根/
├── manage.py
├── middlewares/               # 复制整个文件夹
│   ├── __init__.py            # 注意外层 middlewares/__init__.py 也要在
│   └── request_guard/
│       ├── config.json        # 配置文件（要按需修改）
│       ├── models.py / middleware.py / views.py / urls.py / ...
│       ├── migrations/
│       ├── templates/
│       └── static/            # 内嵌 layui，离线可用
├── <你的项目包>/              # 如 ToHuaShunDownload/ 或 你的项目名/
│   ├── settings.py
│   └── urls.py
└── 你的 app/
```

## 步骤 2：准备虚拟环境与依赖
该中间件**不引入任何第三方库**，只要 Django 能用即可：

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt   # 或只装 Django
```

## 步骤 3：修改 settings.py（共 4 处）

**① 注册 app**（`INSTALLED_APPS` 列表里加一行）：
```python
INSTALLED_APPS = [
    ...
    'Web.apps.WebConfig',
    'middlewares.request_guard.apps.RequestGuardConfig', # 请求守卫
]
```

**② 启用数据库**（`request_guard` 用 Django ORM 存日志/规则，数据库被注释时需要打开）：
```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}
```

**③ 挂载中间件**（在 `MIDDLEWARE` 里加一行，建议放在 CommonMiddleware 之前，让它先于业务逻辑处理）：
```python
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    ...
    'middlewares.request_guard.middleware.RequestGuardMiddleware', # 请求守卫
    'django.middleware.common.CommonMiddleware',
    ...
]
```

**④ 配置已就绪无需其他改动**（模板用 APP_DIRS 自动发现、layui 静态文件由 collectstatic 收集）。

## 步骤 4：修改根 urls.py（挂后台路由）
参考本仓库 `ToHuaShunDownload/urls.py`，在 `urlpatterns` 里加 include，并读取后台前缀：

```python
from middlewares.request_guard.config import get_admin_path as guard_admin_path

urlpatterns = [
    ...
    # 请求守卫后台(前缀由 config.json 的 admin.path 控制)
    path(guard_admin_path().lstrip('/'), include('middlewares.request_guard.urls')),
]
```

## 步骤 5：生成并应用数据库表
```powershell
# 每次刚复制包 / 换新机器都要执行（项目 .gitignore 通常忽略 migrations/，迁移文件不会跟着 git 走）
.\.venv\Scripts\python manage.py makemigrations request_guard
.\.venv\Scripts\python manage.py migrate
```

## 步骤 6：收集静态文件（生产/DEBUG=False 时必做）
后台页面用到的 layui 在 app 的 `static/` 里，正式环境需要收集一次：

```powershell
.\.venv\Scripts\python manage.py collectstatic
```
之后访问 `http://你的域名/static/request_guard/layui/layui.js` 应返回 200。

## 步骤 7：修改配置
打开 `middlewares/request_guard/config.json`，至少改两样：
1. `admin.password` —— 换成你自己的后台密码；
2. `admin.path` —— 把默认的 `request-guard` 换成不容易猜的前缀。
其余字段按需调整（字段含义见文档第二、三章）。

## 步骤 8：启动与验证
```powershell
.\.venv\Scripts\python manage.py runserver 0.0.0.0:8000
```
浏览器打开 **`http://127.0.0.1:8000/<你的admin.path>/`** 验证：
1. 会跳到登录页 → 输入步骤 7 的密码能进入概览；
2. 访问几次首页后，后台「请求日志」能看到记录（UA/来源/身份标签正常）；
3. 在「规则管理」新增一条规则（如 IP 等于 `127.0.0.1`、动作 403）→ 访问首页应被拦；
4. 测完记得删除测试规则。

## 步骤 9：正式上线检查清单（必读）
- [ ] `DEBUG = False`，`ALLOWED_HOSTS` 配好你的域名
- [ ] 后台密码已改（不是默认 `123456`），且 `config.json` 没被提交进 git
- [ ] 后台前缀 `admin.path` 已改成非默认值
- [ ] `trusted_headers` 只保留你真实在用的代理头（防伪造 IP）
- [ ] 用 nginx/gunicorn（或 uwsgi）部署，`/static/` 交给 nginx 或 `collectstatic` 后的 Django 服务
- [ ] `db.sqlite3` 已加入自动备份；如果有多台机器/多进程，注意频控是内存态、各自独立
- [ ] 启用任何"拦截/伪装"动作前先开着后台观察几天日志，确认无误再上
